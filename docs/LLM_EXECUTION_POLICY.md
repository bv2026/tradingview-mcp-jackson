# LLM decision execution policy

The canonical package is one evidence transport artifact containing ten independent strategy contexts. Each strategy request contains that strategy's complete current candidate population, including REVIEW, WATCH, REJECT, and INSUFFICIENT rows where present. There is no pre-LLM top-N filter, WATCH limit, omitted-row reference list, or hydration step. The LLM performs any ranking or candidate selection only after reviewing the complete population for that strategy.

Source file age is checked against `LLM_FRESHNESS_HOURS` (default 48 hours). The package records per-strategy age/status and warnings. The execution wrapper marks stale strategies `PENDING_STALE`; it never changes deterministic scores.

`run:llm-decisions` produces ten request artifacts and a manifest. No provider is bundled or inferred: without `LLM_DECISION_ADAPTER`, these remain `PENDING_PROVIDER`. A future adapter must validate each response against `docs/llm-decision-response.schema.json`, preserve strategy/context version, and reject global, best-overall, or cross-strategy constructs. No order execution is reachable from this layer.

External/manual responses are ingested one strategy at a time with `npm run ingest:llm-decision -- response.json request.json` (the response may also name its `request_artifact`). The boundary checks the response schema fields, request strategy/context version, current package hash, allowed candidate symbols, deterministic-field immutability, and forbidden global language. Valid responses are written as `llm-decisions/<strategy>.json` and marked `VALIDATED`; rejected responses are quarantined under `llm-decisions/rejected/` and never render as current decisions. The minimal future adapter contract is: `generate(request) -> external JSON`, then pass that JSON to this same ingestion boundary; provider status remains `NONE`.
